# AI Data Flow and Privacy

This document describes exactly what information leaves the instance
and under which configuration. It exists because the project is
self-hostable and privacy-respecting, but the external Hugging Face
Inference API is optional — the distinction must be explicit
(MASTER §38: do not claim data "never leaves the instance" when an
external AI API is enabled).

## Data flow diagram

```
Browser (React SPA)
    │
    │  HTTPS + Bearer JWT (Supabase-issued)
    ▼
Backend (FastAPI, self-hosted)
    │
    ├──► Supabase (Postgres + Auth + RLS)   [user data stays in your DB]
    │
    └──► Hugging Face Inference API         [ONLY when use_ai=true AND HF_TOKEN set]
```

## What is transmitted to Hugging Face

When `use_ai: true` is passed to a generation endpoint **and**
`HF_TOKEN` is configured, the backend sends the **prompt** to the
Hugging Face Inference API. The prompt contains:

| Endpoint | Data sent to HF |
|----------|-----------------|
| `POST /api/v1/documents/cv/generate` | name, target role, summary, experience, education, skills, language |
| `POST /api/v1/documents/cover-letter/generate` | name, company, target role, summary, language |

**Not sent to HF:**
- The user's JWT or Supabase credentials
- The user's `user_id`
- Stored documents, applications, or tracker data
- Job search queries or results

## What stays on the instance

The following data **never** leaves your Supabase/database:

- User profile (`profiles` table)
- Generated documents (`documents` table)
- Application tracker (`job_applications` table)
- Authentication state (Supabase Auth)

## Configuration modes

### Offline mode (default)

- `use_ai` defaults to `false`
- `HF_TOKEN` is not required
- **No data leaves the instance**
- Documents are generated by deterministic local templates

### Online mode (opt-in)

- `use_ai: true` on a generation request
- `HF_TOKEN` configured in the environment
- The prompt (user-supplied career facts) is sent to HF
- The response is validated against a Pydantic schema
- A "AI-generated content — review before sending" notice is appended

### Self-hosted inference (future, RD-01)

- Ollama or HF Inference Endpoints on your own infrastructure
- No data leaves your network
- Not yet implemented (see TODO.md RD-01)

## Credentials required

| Credential | Purpose | Required for |
|------------|---------|--------------|
| `SUPABASE_URL` | Database + Auth | Always |
| `SUPABASE_SERVICE_ROLE_KEY` | Server-side DB access | Always |
| `SUPABASE_JWT_SECRET` | JWT signing/verification | Always |
| `HF_TOKEN` | Hugging Face Inference | Only when `use_ai=true` |
| `ADZUNA_APP_ID` / `ADZUNA_APP_KEY` | Job search (Adzuna) | Only for Adzuna provider |

## Data minimization

- The backend never logs prompts, document content, or user facts
  (see `core/observability.py` — sanitized correlation IDs only)
- The backend never logs `Authorization` headers, `HF_TOKEN`, or
  database credentials
- Error responses never include internal details (logged server-side
  only, see `core/errors.py`)

## User rights (GDPR foundation)

- **Access**: users can read their own profiles, documents, and
  applications via the API (RLS-enforced)
- **Deletion**: users can delete their own documents and applications
  via the API; profile deletion is handled by Supabase Auth
  (`on delete cascade` removes dependent rows)
- **Export**: document export (DOCX/PDF) is available for all
  stored documents

> Note: a dedicated "export all my data" and "delete my account"
> endpoint is tracked as a future enhancement (PRIV-01 follow-up).

## Self-hosting guidance

To keep all data on your own infrastructure:

1. Deploy Supabase (self-hosted or managed)
2. Do **not** set `HF_TOKEN` (offline mode)
3. Or run Ollama locally and use the future RD-01 integration
4. Review `docs/security/overview.md` for hardening steps
